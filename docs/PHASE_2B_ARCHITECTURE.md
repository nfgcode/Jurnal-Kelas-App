# Phase 2B — explicit academic workflow foundation

Scope: durable preparation, pure SELECT previews, explicit validation/confirmation/execution and ordered annual coordination. No HTTP/UI/importer, activation or production academic executor. Graduation, promotion and intake are unavailable by default. Never call the legacy combined transition engine.

## Contracts

Namespace `App\AcademicWorkflows`. `WorkflowService`: prepare(kind, source?, target?, items, sourceMetadata, actor), preview(id, actor), validate(id, actor), revise(id, items, sourceMetadata, actor), confirm(id, version, hash, actor), execute(id, confirmationId, actor), retry(id, actor). Actor must be the authenticated persisted active admin. Every administrator has equal workflow authority; confirmations are bound to the specific actor. `Executor::execute(Operation, Preview): array` is synchronous, transaction-owned, must not commit, perform DDL, external I/O or after-commit work. Registry empty by default; test doubles only in this phase. Result contract structural counts only.

States: draft, ready, confirmed, executing, completed, failed, needs_attention. Item validation: valid/invalid/unverified. Revision increments version and clears confirmation. Validation persists current source snapshot and item outcomes; preview never writes or locks. Confirmation binds operation ID, actor, version, snapshot hash, expiry. Execution obtains existing academic singleton FIRST, operation lock SECOND, reloads source evidence with current locking reads, revalidates, then invokes an explicitly registered executor. Completed replay returns persisted result before stale-confirmation checks, but after authentication. No automatic retry: failed/needs_attention reset requires explicit retry, validate and new confirmation. Academic mutation, completed result and success audit share one transaction. Unexpected exceptions become fixed error codes; durable failure records use a separate transaction after rollback. After-commit transport failures must replay completed results without marking failed.

## Persistence

Additive migration `2026_11_01_000001_create_academic_workflows.php`: operations, items, immutable structural audits, coordinators and ordered stages. Source/target nullable (graduation without retention needs source only; intake needs target only). Foreign keys RESTRICT; no destructive legacy alteration. Source metadata allowlist: official_verified boolean, official_reference opaque bounded identifier, source_content_hash lowercase SHA-256, source_version bounded identifier, effective_date explicit YYYY-MM-DD. Item allowlist: student_ref literal NIS, decision, target_class_id, excluded boolean, nisn bounded string, email bounded string, exclusion_reason_present boolean. Exclusion reason text is not persisted. No credentials, names, notes, SQL or arbitrary payload persistence. Snapshots contain allowlisted academic/identity fields only; history missing dates remains unverified.

## Domain readiness

Graduation population is ALL active XII students assigned to source-period classes, not a selected subset. Every student needs an explicit verified lulus/tidak_lulus decision; omitted students appear as synthetic unverified preview rows, never persisted or silently graduated. Official reference, content hash and version identify evidence without uploading a file. Effective date and current clock must lie within source bounds; effective date cannot exceed today. Tidak_lulus requires XII destination. Promotion population is ALL active source X/XI students; omitted decision means naik, but each student requires destination mapping. Effective date must equal verified adjacent destination start; late execution remains blocked. Tinggal_kelas remains same grade; naik next grade, same department/parallel. Intake population is submitted candidates only; NISN (10 digits), email and destination class required. Collisions include all existing siswa NIS/NISN, all users NIS/email regardless of status/role, and all nonexcluded operation items (email case-insensitive). Excluded intake rows bypass their own identity/date/class/department errors only with exclusion_reason_present. Explicit intake effective date must lie within target bounds; no execution-day default. Snapshots record population boundary, complete source roster evidence, candidate identity, clock and effective date, invalidating confirmation on changed dependencies. Validated period bounds, target class/year, department active and dated source history required. Preview adapter consumes `TahunAjaran::formatValid`, persisted `RiwayatKelasSiswa` evidence and the lifecycle consistency contract (no active alumni, matching current membership). `KesiapanTransisi` remains separate advisory legacy UI contract; its global blockers must not gate independent workflows. Its combined executor is never called.

## Coordinator

Fixed graduation, promotion, intake order; minimum two explicitly selected distinct stages. Stage operation may be attached later. No auto dispatch. Explicit executeStage operates only the earliest incomplete stage. Each stage independently commits; failure cannot undo prior completed stages. Resume retries only the failed stage after its operation receives explicit retry/validation/confirmation. Coordinator read projects partial progress from durable operations; completed stages immutable.

## Verification boundary

Only `php tests/run.php` SQLite in this implementation. MySQL migration cycle and deterministic multi-process singleton/operation lock overlap owned by parent integration verifier. SQLite is not MySQL concurrency evidence. No persistent database migration, install, commit or full suite.
